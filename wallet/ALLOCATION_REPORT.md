## 4. 可复现性（这是"随机分配"能被审计的关键）

```
随机种子 : fafe729cdfc7db7992043ec027df470cca1be0cdec0cb4c8a6cbd0401ee8501c
派生规则 : seed_i = HMAC_SHA256(种子, "agora-dev-wallet-seed:i")
           w_i    = 1 + int(HMAC_SHA256(种子, "agora-dev-wallet-weight:i")[:8]) % 999
           分配_i = floor(池子 * w_i / Σw) + 取整余数按索引顺序每钱包 +1 atom
```

任何人在本仓库执行下面两条命令，都会得到**逐字节相同**的分配表 ——
否则"随机分配"就只是"我说了算"，这在治理上是不可接受的：

```bash
python3 tools/agora_dev_wallet.py gen --count 100 --pool-pct 10 --out-dir /tmp/recheck \
    --seed-hex fafe729cdfc7db7992043ec027df470cca1be0cdec0cb4c8a6cbd0401ee8501c
diff /tmp/recheck/dev_wallets.csv wallet/dev_wallets.csv && echo 分配表一致

# 或者直接校验链上余额（把创世 JSON 与分配表逐条对照）
python3 tools/agora_dev_wallet.py check-genesis \
    --genesis wallet/genesis.testnet.json --table wallet/dev_wallets.csv
```

**实测结果：** 100/100 个钱包的链上余额与分配表完全一致；供应量守恒 ✅。

## 5. 必须知道的三件事（治理）

1. **这 100 个钱包是"一个人控制"的。** 私钥全部由本次生成产生在同一台机器上。
   在主网上这**必须公开披露**（谁、多少、依据），这是 GATE-11 的要求；
   "开发者奖励"若没有公开的贡献依据，就是**预挖**，交易所与审计方会按预挖处理。
2. **国库的 90.0% 是"未分配"，不是"已给创始人"。**
   它的用途（生态、社区、金库、销毁）**尚未决定**，必须在主网创世前公开。
   把这么大一块放在一个账户里，本身就是中心化风险 —— 建议在公开方案里拆成
   多签/线性释放/用途受限的多个地址。
3. **空投（F2）没有出现在这份分配里。** 规范允许最多 20%（4,096,000 AGORA）
   通过 Merkle 领取表发放，其分配表目前仍是 `PENDING-MAINNET-VALUE`。
   本分配**不占用**空投额度。

## 6. 私钥纪律（照做，不要问为什么）

| 规则 | 原因 |
|---|---|
| `keys/` 与 `*.seed` 永不进仓库 | `.gitignore` 已排除；一旦提交，历史里永远删不干净 |
| 不要在聊天/邮件/截图里传私钥 | 这些渠道都会留副本，且不受你控制 |
| 生成后立刻转移到离线介质并删除本机副本 | 本机被入侵 = 全部钱包被接管 |
| 验证者私钥（`founder/`）与国库私钥分开保管 | 验证者密钥要**在线**，国库密钥应当**离线** |
| 主网前重新生成验证者密钥 | 本批密钥是在**这台机器**上生成的，安全假设已被削弱 |
